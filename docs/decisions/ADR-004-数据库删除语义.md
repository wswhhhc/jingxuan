# ADR-004：重构后业务删除统一为物理删除

## 状态

已接受

## 日期

2026-07-11

## 背景

现有系统大面积依赖逻辑删除，测试数据、废弃数据和业务残留难以区分，删除后还会继续污染唯一索引、聚合统计和迁移结果。

## 决策

- v2 业务删除统一为物理删除。
- 共享根对象采用 `RESTRICT`，删除前必须返回影响清单并二次确认。
- 聚合内部关系采用 `CASCADE`。
- 旧软删、测试、废弃数据在迁移时不迁移、不备份。
- 奖品发放、排行等需要历史快照的场景，通过专门快照表保留业务事实，而不是靠软删保留脏数据。

## 备选方案

### 继续逻辑删除

- 优点：看似可恢复。
- 缺点：查询、唯一约束、迁移、统计、文件清理都会持续复杂。
- 结论：不采用。

## 结果

- 查询和唯一约束明显简化。
- 迁移规则可以严格定义“有效数据”边界。
