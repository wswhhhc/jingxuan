# ADR-008：生产环境继续 HTTP，显式接受 Cookie 安全折衷

## 状态

已接受

## 日期

2026-07-11

## 背景

项目正式环境目前部署在可信校园网络，同源访问可控，但不具备立即切换 HTTPS 的条件。与此同时，刷新令牌改造要求使用 Cookie。

## 决策

- 生产环境继续使用 HTTP。
- Refresh Cookie 使用 `HttpOnly + SameSite=Strict`，但不启用 `Secure`。
- 系统必须保持同源访问，禁止通配 CORS。
- 登录、刷新、注销接口必须校验 Origin。

## 备选方案

### 因无 HTTPS 而放弃 Refresh Cookie

- 优点：规避 `Secure=false`。
- 缺点：会迫使令牌落到更弱的前端持久化方案。
- 结论：不采用。

### 阶段 1 强制切 HTTPS

- 优点：安全更好。
- 缺点：不符合当前环境约束，不属于本轮重构的交付前提。
- 结论：当前阶段不采用。

## 结果

- 风险被明确记录和接受，而不是隐含存在。
- 后续若环境允许 HTTPS，应以新 ADR 覆盖本决策。
