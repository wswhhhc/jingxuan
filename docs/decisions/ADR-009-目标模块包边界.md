# ADR-009：目标模块包边界

## 状态

已接受，分阶段实施。

## 背景

现有系统按历史功能目录组织，适配层、Mapper 和服务之间存在大量直接依赖。一次性移动全部代码会扩大回归范围，也无法在每一步保持系统可运行。

## 决策

先创建与目标架构对应的 Java 包，并使用 Spring Modulith `@ApplicationModule` 显式登记模块名称。旧模块暂时保留，业务迁移以垂直闭环为单位进行；新代码只能依赖目标模块的公开 API，禁止新增跨模块 Mapper 注入。

目标包与计划模块对应关系：

| Java 包 | 业务模块 |
| --- | --- |
| `identityaccess` | identity-access |
| `referencedata` | reference-data |
| `campaign` | campaign |
| `portfolio` | portfolio |
| `evaluation` | evaluation |
| `communication` | communication |
| `moderation` | moderation |
| `operationsreporting` | operations-reporting |
| `workflow` | workflow |

## 后果

本增量不改变旧 API 和数据库行为，但为后续 ArchUnit/Modulith 边界门禁提供稳定锚点。正式启用 `ApplicationModules.verify()` 前，必须完成旧适配层和 Mapper 依赖的逐模块迁移。
