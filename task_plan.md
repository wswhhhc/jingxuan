## 已做决策

| 决策                                                     | 理由                                                                         |
| -------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 以实际源码、测试和可执行命令为完成证据                   | 避免把目录、注释或提交标题误判为已实现                                       |
| 按依赖顺序增量补齐并保持每个切片可验证                   | 降低全量重构继续推进时的回归风险                                             |
| Git 提交、推送、PR、Release 与 GitHub 描述统一使用中文    | 用户允许完整实施，且项目明确要求所有 Git/GitHub 描述使用中文                 |
| 以自动质量门禁替代人工批准                               | 用户明确要求尽量减少人为干预；验证通过后可自动进入实施、迁移和正式发布       |
| 正式迁移与清理由验证结果驱动                             | 用户已授权实际连接正式环境执行，并授权在验证通过后完成不可逆清理             |
| 当前总体完成度按阶段加权为 31%（±3%）                   | 综合当前 HEAD、实跑门禁、后端/前端/基础设施审计；不把不可达 WIP 计入已完成   |
| `d7ff9ed` 仅作逐 hunk 恢复源                              | 该 WIP 含高价值实现但自身不可编译且基于旧 HEAD，整体恢复会覆盖当前成果        |
| purge 延后至观察窗口和完整生产回归之后                   | 独立对抗审查确认开放流量后立即清理会提前失去恢复来源                         |
| 数据模型采用逐模块 expand→迁移消费者→contract            | 保证每个中间提交可构建，避免在旧消费者迁走前全局删除逻辑删除/数字状态         |
