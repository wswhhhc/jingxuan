# 实施计划：恢复并加固 CI 全链路质量门禁

## 目标

消除 GitHub Actions 后端门禁的级联失败，统一 `/api` 路径语义，恢复 V1 Problem Details 契约，并补齐部署、冒烟与 OpenAPI 语义门禁。

## 实施顺序

1. 路由与错误契约：真实请求统一保留 `/api`；V1 返回 Problem Details，旧接口继续返回 `Result`。
2. 测试隔离与兼容性：修复 Flyway/Testcontainers、限流并发与缓存污染，补齐回归测试。
3. 部署与冒烟：固定 Docker 代理信任边界，移除重复 SQL，重建安全的三角色冒烟脚本并加入 CI。
4. OpenAPI：从实时后端同步已发布 V1 语义，生成稳定快照与客户端，并检测未跟踪生成物。
5. 完整验证：执行工具链、配置、格式、冒烟、OpenAPI、前端、依赖审计和后端 `verify`。

## 风险与控制

- 不恢复已迁移接口的旧实现；相关集成测试改为当前 V1 契约。
- 不跳过或禁用失败测试。
- 每个增量修改后先跑对应测试，再进入下一批。
- Docker 只信任固定 Nginx `/32`，后端端口仅绑定宿主机回环地址。
